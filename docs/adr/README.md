# Architecture Decision Records

Accepted ADRs are normative for the decision they own. Proposed ADRs are non-normative. Superseded ADRs remain in history and link to the accepted replacement. Change an accepted decision by adding a new ADR; do not silently rewrite its meaning.

If an ADR conflicts with implementation or another canonical document, identify the owner and resolve the conflict explicitly. A passing document contract proves structure and recorded wording, not runtime enforcement.
