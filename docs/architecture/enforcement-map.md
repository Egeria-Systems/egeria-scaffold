The exact P0.2 matrix, command meanings, runtime distinctions, deployment evidence, and claim limits are recorded in the [Next.js and Cloudflare compatibility record](../compatibility/nextjs-cloudflare.md). Local workflow structure proves only the repository contract; the recorded successful GitHub Actions run and non-production Worker evidence establish the separate external deployment result.

The deterministic in-memory rendering of YAML 1.2 content and Markdown with validated YAML front matter is guarded by `packages/builder-core/tests/render-skeleton.test.mjs` and the exact source and template allowlists in `tests/package-boundaries/private-packages.test.mjs`. These gates prove returned bytes, strict content shapes, catalog/file boundaries, copy placement, and ownership agreement only. The Markdown body remains opaque data; these gates do not prove safe HTML rendering.

P1 new-directory generation is guarded by `packages/builder-core/tests/generate-project.test.mjs`. Its injected-verifier tests prove exclusive source writes, exact lockfile inventory, pre-state and post-state agreement, state-last ordering, exact installed surfaces, destination refusal, identity-bounded cleanup, and stable failure behavior. The explicit `packages/builder-core/tests/generate-project.integration.mjs` gate separately proves that the exact public packages resolve with their recorded integrity/signature and provenance-exception status, both profiles complete frozen installation plus Next/OpenNext builds, the generated graphs pass the execution-time moderate advisory and registry-signature audits, and final state/inference agree. Neither gate proves workerd runtime, deployment, visual quality, accessibility conformance, translation quality, human usability, or production safety.

The committed portfolio/site golden fixtures are guarded by LF-normalized byte-for-byte regeneration, exact inventory/state/inference checks, and `verify:generated-skeletons`. The fixed-root verifier rejects non-regular paths and unapproved dependency sources or execution policy, validates the exact manifests and workspace policy including the sole approved security override and lifecycle-build allowlist, checks the exact public Egeria package versions/integrities and lockfile policy, and runs frozen install, peer, advisory, signature, lint, typecheck, Next build, and OpenNext build only in identity-bounded temporary copies. It does not preview under workerd, deploy, publish, mutate a provider, assess visuals or translation quality, establish accessibility conformance, or prove general security or production safety.

## Updating enforcement ownership

When a planned gate is implemented, update this table in the same focused change as the executable gate and its test. Record the exact command and result in implementation evidence. Passing a document-structure contract proves only structure and ownership; it does not prove prose semantics or a later runtime gate.
