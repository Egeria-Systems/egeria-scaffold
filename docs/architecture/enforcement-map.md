Local workflow structure proves only the repository contract; the recorded successful GitHub Actions run and non-production Worker evidence establish the separate external deployment result.

The deterministic in-memory rendering of YAML 1.2 content and Markdown with validated YAML front matter is guarded by `packages/builder-core/tests/render-skeleton.test.mjs` and the exact source and template allowlists in `tests/package-boundaries/private-packages.test.mjs`. These gates prove returned bytes, strict content shapes, catalog/file boundaries, copy placement, and ownership agreement only. The Markdown body remains opaque data; these gates do not prove safe HTML rendering.

P1 new-directory generation is guarded by `packages/builder-core/tests/generate-project.test.mjs`. Its injected-verifier tests prove exclusive source writes, exact lockfile inventory, pre-state and post-state agreement, state-last ordering, exact installed surfaces, destination refusal, identity-bounded cleanup, and stable failure behavior. The explicit `packages/builder-core/tests/generate-project.integration.mjs` gate separately proves that production generation resolves the exact public standards `0.1.0` and observability `0.2.0` packages with their recorded integrity and signature/provenance status, completes frozen installation plus Next/OpenNext builds, the generated graphs pass the execution-time moderate advisory and registry-signature audits, and final state/inference agree. Neither generation nor these checks prove workerd runtime, deployment, provider delivery, visual/performance quality, accessibility conformance, translation quality, human usability, or production safety.

The committed portfolio, `portfolio-calendly`, and site golden fixtures are guarded by LF-normalized byte-for-byte regeneration, exact inventory/state/inference checks, and `verify:generated-skeletons`. The fixed-root verifier rejects non-regular paths and unapproved dependency sources or execution policy, validates the exact manifests and workspace policy including the narrow exact first-party release-age exclusion, sole security override, and lifecycle-build allowlist, checks exact public Egeria versions/integrities and lockfile policy, and runs frozen install, peers, advisory/signature audits, lint, Wrangler type generation, typecheck, named unit/component tests, Next/OpenNext builds, isolated Chromium installation, and development/workerd browser tests only in identity-bounded temporary copies.

Observability rendering and inference tests require Workers Logs custom logging with default request/response invocation logs disabled, separately classified platform error/exception logs, and the browser-route test drives a no-`Content-Length` stream past 8,192 bytes and requires immediate cancellation. Generated-reporter tests execute credential-free and referrer-free browser delivery plus the valid and absent Better Stack composition paths. Descriptor and certification tests separately require repository/deployment configuration removal, credential/provider/data disposition and recovery review, plus `cleanup-recovery` evidence before certification.

The observability fresh-scaffold runner passed at evidence revision `ef845b1e0551d3b43e17969cc00f21960c90769b` and supplies only the reviewed local registry entry. The manual protected-staging workflow and provider receipt template are statically checked preparation, not deployed or provider evidence. `waitUntil()` remains best-effort and non-durable; platform/framework logs remain separate provider-controlled records; retention and quotas remain plan-dependent; and exact Next.js/OpenNext compatibility requires the actual pinned build and protected deployment evidence.

The Calendly browser specification intercepts the complete configured provider origin, fulfills only the exact scheduling document with local stub content, aborts and records every unexpected provider-origin request, and asserts that none occurred. It verifies no eager request, popup activation and cleanup, ordinary navigation fallbacks, narrow containment, and selected automated accessibility rules. These recurring gates do not call Calendly, make or confirm a booking, configure or clean provider data, deploy, call the generated HTTPS deployed-mode target, publish, assess visuals, translation quality, human usability, or assistive-technology compatibility, establish accessibility conformance, or prove general security or production safety. A separate one-time provider receipt records the exact-revision protected-staging, provider-confirmed, cancellation, and cleanup evidence; it does not change those automated claim limits or establish ongoing provider availability.

This documentation contract by itself does not prove any runtime or provider result, cleanup, recovery, deployment, or external authorization. The actual registry, gate commands, local receipt, and provider receipt are the distinct evidence owners; this document only names their enforcement and claim boundaries.

## Updating enforcement ownership

When a planned gate is implemented, update this table in the same focused change as the executable gate and its test. Record the exact command and result in implementation evidence. Passing a document-structure contract proves only structure and ownership; it does not prove prose semantics or a later runtime gate.
