# Builder CLI boundary

Read the repository [`AGENTS.md`](../../AGENTS.md), the canonical [package ownership](../../docs/architecture/package-ownership.md), and the [review and contribution protocol](../../docs/governance/review-and-contribution.md) before editing this surface.

`apps/cli` is the private executable adapter for the builder kernel.

- Keep the nine commands exact for this approved increment: `create`, `infer`, `doctor`, `diff`, `plan-add`, `apply-add`, `plan-remove`, `apply-remove`, and `plan-upgrade`. `apply-remove` remains the exact current removal command; `plan-upgrade` is read-only. Parse only command-specific long options and emit one content-safe JSON line.
- Keep command input/output thin. Builder decisions, repository transformations, schemas, profile recipes, state, inference, and diagnostics belong to `packages/builder-core`.
- `create` may call only builder-core's approved new-directory generation boundary. It does not add overwrite, interactive prompt, Git, deployment, publication, provider, or existing-repository mutation behavior.
- `infer`, `doctor`, and `diff` remain read-only and must not install dependencies or change repository bytes.
- `plan-add` remains read-only and is limited to `booking-calendly` with paired validated Calendly settings. Require builder-core's clean attached linked worktree preflight before and after planning, exact canonical managed-surface inventory, application-owned surface availability, rejection of hidden tracked state and ignored create targets, and containment of unexpected reader/Git failures under their stable codes. Return only the redacted plan or refusal code, and never create the worktree or branch. Do not transform, migrate, persist state, install dependencies, or contact a provider.
- `apply-add` is limited to the exact approved `booking-calendly@0.1.0` plan fingerprint in the same clean attached linked worktree. Delegate transformation, isolated generated-project verification, re-inference, migration append, state-last persistence, post-state agreement, exact dirty-path inspection, and recovery classification to builder-core. Emit only the bounded result or refusal/recovery envelope. Never create the branch/worktree, commit, reset, clean, deploy, publish, contact a provider, or treat successful execution as verified-final-diff approval.
- `plan-remove` remains read-only and is limited to exact installed and desired `booking-calendly@0.1.0`. Require the same clean attached linked-worktree preflight before and after planning, exact desired/installed/inferred agreement, canonical surface inventory, exact managed and shared-composition bytes, and consistent ejection metadata. Classify unchanged capability-owned files for deletion and modified capability-owned application-owned files for preservation and ejection without changing them. Return only the redacted approval plan or stable refusal, and never delete, transform, verify, migrate, persist state, install dependencies, create a branch/worktree, or contact a provider.
- `apply-remove` is the exact current removal command and is limited to consuming the exact `plan-remove` fingerprint for `booking-calendly@0.1.0` in that same eligible linked worktree. Delegate ownership-aware deletion, replacement, preservation/ejection, isolated verification, re-inference, migration append, state-last persistence, exact final agreement, and exact final Git-diff inspection to builder-core. It may add no settings, generic transformation, provider, credential, persistent-data, cleanup, or automatic rollback behavior, and success remains subject to separate verified-final-diff approval.
- `plan-upgrade` remains read-only and is limited to exact inferred and installed `standards@0.3.0` targeting `standards@0.4.0`. Accept only an absolute existing linked-worktree directory and the exact capability/target arguments; never accept a caller-supplied source version. Require the same clean stable attached linked-worktree preflight before and after planning, reject ignored create targets, and delegate endpoint snapshots, version-graph resolution, desired/installed/inferred/project/state/migration agreement, drift/ejection/state refusal, control-file fingerprints, and exact actions to builder-core. Emit only the privacy-safe plan or stable refusal. Do not transform, verify generated behavior, migrate, persist state, execute an upgrade, create a branch/worktree, or contact a provider.
- Test this adapter with Node's test runner (`node --test`) through `pnpm run test:cli`. Cover argument parsing and process/output contracts with focused unit and subprocess tests. The compiled `plan-upgrade` integration uses representative temporary linked worktrees and exact no-mutation assertions. The compiled `apply-add` and `apply-remove` integrations execute builder-core's isolated ordinary generated-project verifier; other CLI checks do not independently prove that behavior. No CLI test proves browser, workerd runtime, deployment, provider behavior, visual quality, accessibility conformance, or production readiness.
- Do not expose this application as a public package.
- Follow the currently approved increment and stop at its review gate before expanding this boundary.
