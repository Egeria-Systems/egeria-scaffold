# Standards package boundary

Read the repository [`AGENTS.md`](../../AGENTS.md), the canonical [package ownership](../../docs/architecture/package-ownership.md), and the [review and contribution protocol](../../docs/governance/review-and-contribution.md) before editing this surface.

`@egeria-systems/standards` is a public, replaceable configuration package. Its current source API includes the strict TypeScript configuration, the strict type-aware TypeScript ESLint flat-config factory, the Cloudflare-isolation ESLint flat config, and the reviewed-but-unpublished copy-externalization flat-config factory.

- Add a standard only when it has a concrete consumer and an approved stable API.
- Keep this package free of runtime application code, a root export, profiles, generators, providers, analytics, observability, and user-visible copy.
- Preserve provider-neutral boundaries. The Cloudflare lint API may identify forbidden imports but must not introduce Cloudflare runtime code.
- Keep Prettier as the formatting owner. The strict ESLint factory composes only the pinned `strictTypeChecked` and `stylisticTypeChecked` presets and must remain behaviorally tested under its declared ESLint peer majors.
- Keep copy enforcement limited to static user-visible JSX, relevant attribute, and Next.js metadata literals with exact centrally configured invariant escapes. Do not add autofixes, wildcard escapes, data-flow inference, locale-key machinery, or parity validation before a concrete consumer contract exists.
- Keep exports and packaged files explicit. Local release configuration never authorizes publication.
- Test public configuration behavior with Node's test runner (`node --test`) through `pnpm --filter @egeria-systems/standards run test`, including supported ESLint peer behavior and packaged-file contracts. The generated Vitest configuration remains source-generated by builder-core; do not add a public Vitest preset without a separate extraction, consumer, compatibility, Changeset, and release gate. Passing package tests do not prove generated project or browser behavior.
- Follow the currently approved increment and stop at its review gate before expanding this boundary.
