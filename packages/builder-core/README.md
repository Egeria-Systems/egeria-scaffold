# `@egeria-systems/builder-core`

Private ownership boundary for Egeria Systems builder internals.

Builder-core owns executable runtime contracts for capability descriptors, profile recipes, desired project configuration, installed state, and successful migration records. Zod schemas are canonical; checked Draft 2020-12 artifacts live in `schemas/`. After building builder-core, regenerate them with `pnpm run schema:generate` or verify them without writes using `pnpm run schema:check`; `pnpm run verify` runs the required build first.

Builder-core also owns the private certification registry schema, canonical subject digest, private-artifact validation, descriptor admission, and closure policies consumed from [`certifications/capabilities.json`](../../certifications/capabilities.json). Admission requires exact coverage for every executable descriptor and rejects stale versions or behavior-contract digests. `booking-calendly@0.1.0` and exact `standards@0.3.0` are certified; `observability@0.3.0` is ordinary `pending` with empty evidence, and four unchanged subjects remain `backfill-pending`. Standards is bound to a private independently reviewed eight-outcome local receipt renewed at post-Plan-A descendant `d7c63b0aaa9bebd56c075f16f1e5d86519853698` and integrated at accepted `main@7b5324cfcffc7eb94f48cc304cbfe0ceb08c3486`. The earlier observability 0.2 private protected-staging receipt remains evidence only for that exact historical subject; the new 0.3 subject claims no certification outcome. Clean-checkout CI validates the tracked registry contract, exact descriptor admission, and requested closure policy without reading ignored plans or receipts. Before a certification workflow updates the registry, `pnpm run check:private-capability-certification` explicitly validates private artifact presence, receipt content, review status, and evidence ancestry. Admission passes, while closure rejects the pending observability subject and the four frozen backfills. Certification remains exact-subject private evidence, not public CI evidence, production readiness, or ongoing provider availability.

The runtime Zod schemas are authoritative for repository validation. The checked Draft 2020-12 artifacts are byte-current structural contracts and can be broader or less restrictive where the current Zod-to-JSON-Schema conversion cannot represent a runtime refinement. Consumers that require the complete contract must use the runtime schemas; schema currency does not claim full semantic parity between the checked artifacts and every runtime refinement.

The catalog boundary owns the exact seven executable capability descriptors for `portfolio` and `site`, their current materialized recipe `0.8.0`, readable retained `0.1.0` through `0.7.0` provenance, deterministic dependency-first resolution, and projection into installed-capability manifest entries. `booking-calendly@0.1.0` is the only optional initial-scaffolding capability and does not change either recipe default. Generation uses immutable, separately verified standards `0.1.0` and observability `0.3.0` package pins. Public package probes require exact stable versions; workspace, file, Git, URL, range, tag, and prerelease specifications are rejected without being echoed in issues.

The state and ownership boundary owns strict YAML 1.2 `project.yaml`, JSON `state.json`, and successful-record JSONL migration codecs. Calendly selection and settings must be present together. Observability declares its package/marker, application-owned instrumentation/adapters/route, and inference-only values inside deployment-owned Wrangler configuration without overlapping file ownership. The boundary also owns deterministic SHA-256 fingerprints over exact file bytes or canonical RFC 6901-selected JSON values and pure descriptor-to-installed-surface materialization. These APIs do not create or read repository files.

The repository-inference boundary owns fixed-root read-only text access and deterministic capability and surface evidence. Filesystem reads reject unsafe paths and requested-path symlinks, require regular files beneath a non-symlink root, cap content at 1 MiB, and require valid UTF-8. Inference reads only `.egeria/state.json`, catalog-declared probes, and valid-state managed surfaces; it returns stable metadata and codes without actual repository values or source content.

The diagnostic boundary owns `doctorRepository` and `diffProject`. Each operation reads the required `.egeria` control files, declared probes, and valid-state managed surfaces through one per-operation cache. Doctor returns stable codes for invalid control contracts and desired, installed, inferred, or surface disagreement. Diff returns explicit structural difference kinds. Neither API returns source content, writes a repository, authorizes a transformation, or claims that a repository is safe to change.

`renderSkeleton` performs deterministic in-memory rendering from explicit allowlisted templates for the `portfolio` and `site` recipes, keeps copy in validated YAML 1.2 and Markdown with validated YAML front matter data, renders only the four source-registered typed section shapes, and emits a responsive pure Server Component interface. The `section-composition` capability owns Tailwind CSS and PostCSS configuration and presentation source. The hybrid `standards` capability owns named generated Vitest unit/component projects plus Playwright/axe browser-quality surfaces. Its Node unit project verifies the generated content parser; its jsdom component project renders the actual generated `ContentPage` with Testing Library; Vite's native TypeScript-path resolution keeps both projects aligned with generated application aliases. `observability` owns bounded Next.js request/browser instrumentation, web-vitals reporting, credential-free and referrer-free same-origin browser delivery, a strict ingestion route that cancels streams beyond 8,192 bytes, provider-neutral reporters, and one explicit Cloudflare context adapter. It also owns five error surfaces: local and global App Router boundaries, externalized error copy, its typed copy reader, and the pure fallback presentation. Workers custom records receive only bounded safe operational events; the optional Better Stack diagnostic adapter alone receives bounded restricted error reports through the exact two declared runtime secrets. Replacing Better Stack requires only another adapter and composition change. Message and stack sanitization reduces exposure but is not a privacy guarantee, and stack strings are not source-map deobfuscated in this increment. Workers Logs still require head sampling `1`, invocation logs disabled, and `CF_VERSION_METADATA`; observability installs no analytics or browser storage. Cloudflare platform error/exception logs are separately classified and remain certification-bound. Its reviewed removal/recovery contract keeps generated source, deployment configuration, credentials, provider resources, retained data, and recovery separate.

When explicitly selected, `booking-calendly` accepts only paired strict settings: `link`, `inline`, or `popup` plus a bounded HTTPS `calendly.com` or `www.calendly.com` destination with a non-root path and no credentials, query string, fragment, normalization whitespace, or non-default port. Link mode remains an ordinary anchor. Inline mode activates a direct cross-origin iframe near the viewport; popup mode enhances the ordinary anchor with a native dialog and user-activated iframe. The generated source loads no Calendly host-page script or API. Rendering returns the validated desired project, resolution, sorted file bytes, and ownership descriptors and reports stable sanitized failures without rejected destinations.

`generateProject` owns bounded creation of one previously absent destination. It injects the immutable verified package versions, writes rendered files and project configuration exclusively in an identity-recorded sibling temporary directory, accepts only one new regular lockfile from the injected verifier, requires probable pre-state inference, delegates isolated verification, writes an empty migration log and validated installed state last, requires confirmed post-state inference with no managed drift, and commits with one rename. Failures clean only an identity-matching source temporary directory. The verifier is an effect boundary; it owns no catalog, state, or lifecycle decision.

`createPnpmGeneratedProjectVerifier` is the concrete effect adapter. It requires pnpm `11.20.0`, prepares the lockfile with scripts disabled and a builder-owned external store, copies the source into a separately owned validation directory, and runs the frozen install, lint, typecheck, named unit/component tests, Next build, and OpenNext build there. Child processes receive only a narrow platform/process environment, a blank home and npm configuration, the public npm registry, and disabled Next telemetry. Commands use argument-array `execFile` calls with bounded time and output; child output is never returned. Validation and support owners are identity-checked before recursive cleanup.

Portable filesystem rename does not provide a hostile-concurrency no-clobber guarantee on every supported platform. Generation checks destination absence immediately before rename and preserves destinations observed before that check; a target created after the check may still be replaced where the platform's rename semantics permit it.

Current generated-testing evidence for the three retained fixtures proves deterministic production generation, desired/installed/inferred agreement, portable public packages, frozen install, peer checks, audit/signature verification, Wrangler types, lint/typecheck, named unit/component tests, Next/OpenNext builds, and local development/workerd Chromium checks. The exact standards subject is certified from the separately reviewed fresh-scaffold, test-count, state-agreement, build/browser, retained-matrix, and static CI-contract outcomes. The current `observability@0.3.0` subject remains ordinary `pending` with empty evidence under a future private local restricted-error-diagnostics certification plan; no certification has run for it. The private protected-staging receipt remains historical evidence only for the prior `observability@0.2.0` subject. Current `0.3.0` fixture evidence does not prove deployed/provider receipt, retention, cleanup/recovery, durable delivery, production readiness, privacy completeness, visual quality, human accessibility, or WCAG conformance. `waitUntil()` remains best-effort and non-durable, Cloudflare platform/framework logs remain separate provider-controlled records, and provider retention and quotas remain plan-dependent.

Existing-repository transformation, clean-Git enforcement, migration execution, persistent-data rollback, provider configuration/action/cleanup, recovery automation, and every later capability remain outside this increment. The private CLI is the current thin consumer of generation, inference, and diagnostics; it owns no builder decisions. A separate project-schema package is intentionally absent.

The canonical API and lifecycle owner is [package ownership](../../docs/architecture/package-ownership.md).
